# paper-analyzer 论文分析技能 — v1.6.0

默认是一位帮助读者把论文讲透的研究伙伴：解释问题、核心直觉、方法如何运行，以及证据支持到哪里。支持 PDF、Markdown、论文链接及粘贴的正文或摘要；输出语言跟随用户，材料读取和可视化能力取决于客户端。

## 使用方式

提供**阅读、审稿、对比**三种模式。阅读默认深入讲解论文，按用户要求调整讲解深度、篇幅和顺序。

| 请求示例 | 行为 |
| --- | --- |
| “帮我读这篇论文” | 默认深入讲解，沿问题、前序思路、核心直觉、方法、证据和边界展开 |
| “速读，只要五条要点” | 压缩范围，保留关键机制、结果条件与重要边界 |
| “按章节精读，包括附录” | 保留源编号与顺序，覆盖指定章节；解释公式与可见图表 |
| “以审稿人的视角讲清这个方法” | 以讲解为主，在相关机制和结论处检查假设与证据 |
| “写一份审稿报告” | 评估优势、不足、声明与证据、验证条件及关键问题；默认不评分 |
| “对比这四篇论文” | 覆盖全部论文，先检查可比性，再给有条件的结论 |
| “只解释公式里的温度参数” | 回答局部问题，复用已读材料，不重写全篇 |

用户指定的篇幅、顺序、格式和图表偏好优先。阅读以理解难点分配篇幅，不强制输出固定章节、思维导图或复现表。只解释原文时，不额外加入审稿意见；材料不全时，仍可进行明确限定范围的分析。

## 如何讲清楚

- **研究逻辑**：说明已有思路解决了什么、剩余瓶颈是什么、关键观察如何导出方法，并区分直觉与验证。
- **贯穿示例**：跟踪同一个实例的输入、中间状态与输出。优先采用原文案例，自建教学示例明确标注，不补造未公开的细节。
- **公式解释**：首次出现时定义符号、索引、必要维度与假设，解释数学操作和关键推导；后续沿用定义。
- **可视化**：按困难选择流程图、曲线、分布、几何图或有帮助的交互，穿插在解释中。区分原文图表、公式推导、教学示意和实际运行结果。
- **背景与复现**：用户要求调研时实际检索，围绕直接相关的研究背景与前序方法展开；区分发表时背景和后续进展。复现准备度按任务需要展开。

## 质量约定

关键数字和批评必须能够回到原文章节、表格、图或证明。自然区分作者报告、已核实的相关文献结论、有依据的推断和未经验证的猜测。未知不等于缺失，不适用不等于失败。

按实证机器学习、理论、综述、数据集/基准、系统/算法及定性/观察研究选择标准。复现准备度与科学证据强度分开；未运行时不声称复现成功或失败。不同实验条件下的数字不能直接排名，复杂度不等于实测速度。原文优先于译文，缺失图像和损坏公式需要明确标记。

本技能支持论文讲解和汇报内容准备；不负责新论文写作、纯全文翻译、通用幻灯片设计或 PDF 转换。需要这些交付物时，由宿主使用相应能力处理。

## 文件结构

```text
paper-analyzer/
├── SKILL.md                         # 三模式路由、用户偏好、按需加载
└── references/
    ├── evidence-handling.md         # 来源、证据状态、数值溯源与背景检索
    ├── paper-types.md               # 不同论文类型的适用标准
    ├── explanation-guidance.md      # 机制、贯穿示例与公式解释
    ├── visualization-guidance.md    # 图形选择、来源与宿主能力适配
    ├── modes/
    │   ├── reading.md              # 阅读讲解，适配深度和顺序
    │   ├── review.md
    │   └── comparison.md
    ├── review-standards.md          # 审稿判断与证据力度
    ├── reproducibility-checklist.md # 按需评估验证准备度
    └── mermaid-templates.md         # 按需选择的结构图模板
```

分发或安装时使用整个 `paper-analyzer/` 文件夹，包括参考文档；仓库根目录不是技能入口。技能本身不依赖 Python 包或额外可执行脚本。

## 维护与验证

模式路由与阅读适配原则统一定义在 `SKILL.md`。保持有效 YAML frontmatter、引用路径和各参考文件的一致性。检查输出是否解释清楚关键机制，而不只检查是否具有特定标题。

公开合成材料与行为标准保存在 [tests/scenarios.md](tests/scenarios.md)；验证范围和实际结果记录在 [验证记录](tests/validation-2026-11-02.md)。私人论文放在 `tests/private/`，临时生成文件放在 `tests/generated/`，这两类目录不提交。合成场景不替代真实 PDF/OCR、网页获取、图表渲染或交互的集成验证。
